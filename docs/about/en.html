Why SimpleOpenCV?

A place to experiment with computer vision: separate the signals, change the mathematics, assemble a pipeline and save what works.

The starting point: experiments in SimpleCV

The project began with the author's experiments in SimpleCV: separating red, green and blue channels, displaying them individually and subtracting individual channels between frames. This made it possible to inspect changes that an early conversion to grayscale can hide.

Those experiments suggested an environment where one assumption could be changed at a time: a channel, weight, threshold, filter or equation. Its effect should be visible immediately, without constantly switching between source files.

OpenCV 2.4 as the primary processing foundation

The codebase builds on the Simple-OpenCV repository. OpenCV 2.4.13.7 remains the primary engine to maintain continuity with earlier experiments, teaching examples and algorithms. SimpleCV inspired the approach; this application is not an official successor or a copy of the SimpleCV library.

The ComputerVision-MachineVision and SI_Eksperimenti_Strojnega_Vida collections are associated with the project's research and teaching examples. Third-party material retains its original licensing terms.

From scripts to configurable blocks

The application grew into a visual laboratory, initially called SimpleMotocam and now named SimpleOpenCV. Assemble algorithms from blocks, connect their channels and adjust parameters. An empty block accepts custom code. Find additional examples in the library, save a successful configuration and export it for reuse.

RGB carries image data. The added A channel is a derived confidence weight under a chosen model, not a separate camera measurement or an automatically calibrated probability. The model itself is open to experimentation and validation.

Learning and comparing results

The in-app classroom connects mathematical explanations, detection sequences and examples in different programming languages. The aim is to understand why a sequence works, try alternatives and compare results. Geometry and metrology are directions for further development.

Why a browser edition?

The HTML edition makes the application usable on an ordinary domain. Genuine OpenCV 2.4.13.7 is compiled to WebAssembly, with core and imgproc supporting the current blocks. OpenCV.js 4.13.0 is an optional second engine. The selected version is saved with the algorithm, allowing deliberate comparisons.

Processing runs on the user's computer. Hosting serves files and needs no Python server. Custom code in the HTML edition runs in JavaScript; custom Python/C/C++/Java code requires the desktop or an appropriate server environment. Translations are prepared in advance; translation models are not loaded into the browser.
